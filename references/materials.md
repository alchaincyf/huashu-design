# 素材先行：画面的主角不该只是字和卡片

纯 HTML/CSS 能做的材料如果只剩「字＋卡片＋表格＋细线」，换什么风格都会显得单调——这是旧版产出单调的第二个根因。这份文件解决两件事：每个方向先定主角素材；按用户手里实际有的能力分档，没有的能力推荐安装但绝不卡住。

## 原则

1. **每个方向先定主角素材**，写进方向卡（`references/directions.md`）。别让三个方向都是「纯排版」；用纯排版时要是有意的排版——字本身成为图像（巨字、竖排、裁切），不是标题加正文的默认排法。
2. **内容必需的图先取齐再设计**。介绍动物、地点、人物、产品、历史的设计，图是内容不是装饰；鹦鹉网站没有鹦鹉 = 失败。拿不准时按内容必需处理。
3. **真图诚实性测试**：去掉这张图，信息有没有损失？没有损失 = 装饰，不加。别配 stock「灵感图」。
4. **该是图的地方就放图，不拿 emoji、手画 SVG、灰色占位块顶替。** 界面里的头像、菜品、商品、房间、风景、封面、插画、角色，页面里的主视觉和配图，都算。emoji 当图标、SVG 画人画物、一块写着「图片」的灰底，观众一眼就认出是没做完的 AI 稿，整份设计的可信度跟着掉。几何、图标、数据图、地图线框本来就该用代码画，不在此列；剪影遮罩只用于构图（裁切照片、做形状），不能拿来代替产品图。

**涉及用户本人或他的产品时，真实素材优先**：先查用户私有 memory / config 目录下的 `personal-asset-index.json`（首次使用把 `assets/personal-asset-index.example.json` 复制过去填真实数据；真实数据不放 skill 目录，免得随分发泄露）。找不到就问用户要，不编造。

## 先探测能力

```bash
# $HD = 本 skill 的根目录（SKILL.md 所在目录），不是用户的项目目录
python3 "$HD/scripts/capabilities.py"
```

它查你大概在哪个 agent 环境里、本机有没有能借来生图的 Codex、装了哪些相关 skill、ffmpeg / playwright 在不在，然后列出这次要用图时该按什么顺序找来源。环境是从环境变量猜的，探测不到不代表没有：你自己的工具清单里有生图工具，或用户说有，就以那个为准。

## 图从哪来：按这个顺序，前一个不行再用后一个

1. **你所在的环境自带生图工具**（Codex 的 image_gen、豆包、WorkBuddy 这类）：直接生成。工具返回的是图片网址时（豆包），立刻下载到项目的 `assets/img/`，页面只引用本地副本，临时网址会过期。界面里每一处要图的地方都生成，同一处出两三张，打开看，挑最合适的那张放进去。
2. **你自己不能生图，但本机有登录过的 Codex**（比如你在 Claude Code、DeepSeek harness 里）：借它生成。

   ```bash
   python3 "$HD/scripts/gen_image.py" --prompt "一碗刚出锅的红烧肉，俯拍，深色粗陶碗，自然窗光，旧木桌" --out 项目/assets/img/pork.png --size 1200x900
   ```

   一次一张、串行跑，一张两三分钟。脚本只认 Codex 自己目录里本次新生成的图，没生成出来会报 ✗、不留文件——拿不到生图能力的 agent 会用代码拼一张图交差，所以不看「文件在不在」。
3. **装了生图 skill**（huashu-gpt-image、lovart-api 等）：按那个 skill 的方法生成。
4. **用户给的生图 API**：环境变量里有 `OPENAI_API_KEY`（GPT-Image 2.6）或 `ARK_API_KEY`（字节 Seedream 5.5）时，`gen_image.py --via api`。前三条都没有、而这个设计明显需要图时，**开口向用户要一次**：一句话说明要几张图、推荐这两家（效果最好）、key 放进环境变量而不是贴进对话；他不想给，就往下走。按张计费，花的是用户的钱：一处先出一张，不合适再出第二张。
5. **都没有：开放许可的真图。** `python3 "$HD/scripts/fetch_images.py" --query "英文关键词" --out 项目/assets/img`（Wikimedia Commons，带许可输出），不够再找 Unsplash、Pexels、Openverse。用了 CC BY 类图片，在页面或交付说明里写作者和许可。
6. **五条都走不通**：停下来告诉用户缺什么（一句话：缺哪几张图、装什么或给什么就能补上），那几处先空着并在交付说明第一行写明。这是没做完的状态，不是一种做法。

生成图和真图怎么选：要的是「这一类东西的样子」（一碗面、一间客厅、一位跑步的人）用生成图，能配合页面的颜色和光线；要的是「这一个具体的东西」（某个真实地点、某件文物、某个具名产品、某位真人）用真图或官方图，生成的会是假的。生成前把页面的主色、明暗、画幅写进提示词，出来的图才和界面是一套；提示词写具体的主体、角度、光线、材质，不写「高级感」。

三方向初稿阶段每个方向的主角素材就按这个顺序取到，不等选定方向之后：用户选的是看得见的样子，一个方向用真图、另外两个用色块，比的就不是设计了。时间紧时每个方向先保证最关键的一两张，其余在选定后补齐，并在摆出来时说明哪些还没补。

## 三档

### T0 · 所有用户都有（默认，不依赖任何额外能力）

- **真图**：`python3 "$HD/scripts/fetch_images.py" --query "英文关键词" --out 项目/assets/img --count 2 --width 1600`（Wikimedia Commons，带许可输出）。用户自己的产品走品牌资产协议取官方图。
- **具名产品的 logo**：设计里出现几个可识别的产品就取几个（svgl → simpleicons → favicon，见 `references/brand-asset-protocol.md`）。清单里有一个没取到就补，实在取不到才退诚实占位并明说。
- **程序化材质**（单文件可用，不需要 fetch）：
  - SVG 滤镜：`feTurbulence` + `feDisplacementMap` 做纸纹、噪点、墨迹晕染、印刷错版
  - CSS：多层 `radial-gradient` 做光照和体积，`mask-image` / `clip-path` 做剪影与裁切，`mix-blend-mode` 做套印
  - canvas 生成图：等高线、点阵、流场、星图、织物纹理（固定随机种子，截图可复现）
  - Three.js（`<script src>` 从 cdnjs 加载，`file://` 下可用）做程序化几何、材质与光照
- **数据即图像**：把内容里的数字做成主视觉——一条横跨全页的刻度、按比例缩放的实物、地图上的路线——而不是三个大数字卡片
- **实物仿制**：用 HTML 做票据、标签、证件、说明书、明信片、报纸版面，带纸张、打孔、印章、折痕
- **字即图**：超大字形切出画面、竖排、字形与图片咬合

### T1 · 有 AI 生图能力

判定：上面顺序里的前三条有任何一条走得通——你所在的环境自带生图工具、本机有能借的 Codex（`gen_image.py`）、或装了生图 skill；用户明说有也算。只有 API key 不算：本 skill 没有直接调生图 API 的脚本。

- **方向板阶段先出探针图**：每个方向生成一张氛围或主视觉图（材质、光线、主体），和 HTML 初稿一起摆给用户。写代码之前先有视觉层，用户选的是「看得见的样子」。
- **选定后生成主视觉、插画、纹理、人物与场景**。提示词写具体视觉特征和真实参照名，不写「高级感」「极简」这种形容词——方法见 `huashu-gpt-image`。
- 生成图要过真图诚实性测试，品牌产品图要以官方参考图为基底生成，不凭空画产品。

### T2 · 装了兄弟 skill

| skill | 能多做什么 | 公开地址 |
|---|---|---|
| huashu-gpt-image | 生图 prompt 方法论，配图、海报、信息图、UI mockup | `npx skills add alchaincyf/huashu-gpt-image` |
| huashu-art-motion | 36 种艺术与解说动画风格，口播驱动整片 | `npx skills add alchaincyf/huashu-art-motion` |
| huashu-md-html | md 转出版级 html / PDF / EPUB | `npx skills add alchaincyf/huashu-md-html` |
| huashu-3djs、huashu-flow-diagram | 程序化 3D 场景、会流动的架构图 | 尚未公开，本机装了就用 |

## 缺能力时怎么说

不阻塞，降到 T0 继续，交付时一句话告诉用户能多拿到什么：

> 这版主视觉用的是程序化纸纹＋公共领域插画。装上 huashu-gpt-image（`npx skills add alchaincyf/huashu-gpt-image`）后，下次可以直接生成主视觉和探针图。

只推荐和这次任务相关的一个，不要列清单推销。

## 取图失败时

照「图从哪来」的顺序往下走一级，不是退回 emoji 或色块：生成不出来（额度用尽、被拒）→ 换另一个生图来源 → 换开放许可的真图 → 换一个更容易取到的画面（拍不到这道菜的成品，就用它的食材）。全部走不通才是第 6 条：告诉用户，那几处空着，交付说明第一行写明。
