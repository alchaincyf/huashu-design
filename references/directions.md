# 三方向：三种好设计，不是三种皮

任何新视觉设计，先出三个方向的真实初稿给用户选。这道门本身不变：100% 触发、指定风格或品牌也不豁免、摆出来就停、选择落档 `direction-approved.md`（豁免条件见 SKILL.md「窄桥」）。

这份文件讲**三个方向怎么生成**。

## 为什么这样做（三轮问题与盲选的结论）

**第一轮问题：三版只换了皮。** 三版常常是同一个骨架换颜色和字重。差异要落在版式结构上，不是配色上。

**第二轮问题：隐喻用力过猛。** 强制每版先定一个「大想法隐喻」，页面被整个做成档案柜、借书卡、地铁线路图，用户盲选 4 题输 3 题。

**第三轮问题：约束太多，变无聊。** 为了避开「AI 默认外观」，曾经限制三版里最多一版暖纸衬线，并把深底单点缀、细线报纸这些外观家族列成黄灯。结果三版一起退到浅冷色、规整网格，用户说「太规整，太无聊了」，又输给了不加这些约束的旧做法——而旧做法里他认可的几版，恰好就是深底单点缀、暖纸衬线。

所以现在的做法是**加选项，不加禁令**：三套逻辑照旧，每套出两个候选、写成六张方向卡，挑最强又最不一样的三张做完整版；风格从看得见的样张里选，参考从真截图里拆。外观家族不再是毛病，只有三版挤在同一个家族、或和最近交付过的项目撞了，才需要换。

## 流程

### Phase 1 · 澄清需求＋主动索要参考

这是整个项目唯一的一轮提问（选定方向后不再重问，`references/workflow.md` 的题库从这里挑），一次最多 3 个问题：受众 / 核心信息 / 情感基调 / 输出格式。同时一次问全参考材料：项目叫什么、有没有 logo / 品牌色 / VI / 字体规范、有没有「就要那种感觉」的网站或截图；都没有就说一句「你看着办」。

用户不回应就不枯等：按最佳判断补齐假设（标 assumption），直接往下做，用「看得见的东西」代替继续追问。

给了具体品牌或产品名（能去官网找到 logo 的那种）→ 加走品牌资产协议（`references/brand-asset-protocol.md`），三个方向全部基于同一套真实资产，差异在诠释。普通主题名（咖啡、历史、健身）不是品牌，别去找「咖啡的 logo」。

### Phase 2 · 顾问式重述

用自己的话重述本质需求、受众、场景、情感基调、用户没说出口的期待。以「我直接做 3 个不同方向的真实版本给你看」结尾，不要以「你想选哪个方向」结尾——没看到视觉之前的选择是无效的。

### Phase 3 · 固化 spec

写一份详尽的设计 spec，它是三个方向的共同输入：项目是什么、受众与场景、核心信息分点、情感基调、**输出格式与尺寸（必填，三版必须统一，否则没法横比）**、已知约束、图片需求。spec 只写「要说什么」，不写「长什么样」——长什么样是方向卡的事。

### Phase 3.5 · 素材前置

按 `references/materials.md` 先判档位、取齐内容必需的真图和具名产品的 logo，三个方向共用。

### Phase 4 · 六个候选 → 六张方向卡 → 挑三张

开写之前先看三样东西：

```bash
# $HD = 本 skill 的根目录（SKILL.md 所在目录），不是用户的项目目录
python3 "$HD/scripts/learn.py" direction color <题材关键词>   # 这个用户的偏好＋过去的教训
python3 "$HD/scripts/design_lint.py" ledger                     # 最近交付过的样子和用过的参照：这次不再用
```

再用看图能力打开风格总览：`$HD/assets/style-specimens/sheet-<分区>.jpg`（分区：web / ppt / info / app / xhs 小红书，外加跨媒介的 east 中文与东亚）。一张图里是这个分区全部风格的样张，先知道每个风格做到位是什么样。

**4a · 三套逻辑，每套出两个候选（共六个）：**

- **最佳设计师 ×2**：深呼吸，认真想——假如预算没有上限，世界上最适合为「这个用户、这个题材」做设计的工作室或设计师是谁？想出两位气质不同的（一位大胆、一位克制；或一位西方、一位东亚）。启用他的设计思维从头做，不模仿他某件作品的外观。别总是同几个名字：Pentagram、原研哉、Vignelli 之外，还有吕敬人、杉浦康平、田中一光、服部一成、Irma Boom、Experimental Jetset、Collins、Studio Dumbar……
- **现实参照 ×2**：选两个和需求**同一媒介**、你确定设计极出色的真实作品——做 App 找 App（Apple Design Awards、App Store Awards 入围作品，id 表在 `references/app-paradigms.md`，用 `appstore_shots.py` 取图），做网站找网站（Awwwards 年度、品牌官网），做 deck 找出版物与提案，做信息图找报刊图解（SND、Malofiej 获奖作品）。同媒介的参照能直接迁移版式；跨媒介的（把 deck 做成企鹅封面、把 App 做成标本台纸）实测不是过头就是无聊。用 WebSearch 核实它存在，然后**截下来看**：

  ```bash
  python3 "$HD/scripts/ref_board.py" <作品网址或图片网址> [<第二个>] --out refs/board.jpg
  ```

  用看图能力打开参考板，再量一遍：

  ```bash
  python3 "$HD/scripts/ref_card.py" measure refs/board-1.jpg      # 色板与面积占比、留白多少、内容集中在画面哪几段
  ```

  把借的东西写成具体规则，用量出来的数替掉形容词：网格几栏、标题和正文字号比、主色占比、图文关系。截不到（反爬、WebGL 黑屏）就换同作品的报道页或图片，或请用户发截图；都不行就在卡上写「未亲眼看到」，不假装看过。
- **秒数轮盘 ×2**：取当前秒数 S（`date +%S`；Windows PowerShell 用 `(Get-Date).Second`），从 `references/design-styles.md` 对应分区抽 `S % 分区风格数 + 1` 号，再从 east 分区抽 `S % 12 + 1` 号。编号就是条目在分区里出现的顺序，和样张文件名、总览图格子上的编号一致。先打开抽到风格的样张图（条目里的「样张」一行），看清它做到位的样子再写卡。抽到和外观账本最近 3 个交付同类的，顺延下一号；还原度 <70% 的标注哪部分降级。轮盘的作用是把你带去自己不会主动选的地方。

**借一层，不借一身（最佳设计师、现实参照、轮盘样张，凡是有来源的候选都适用）。** 参考看得越清楚，越容易做成它的翻版。看要看原图、量数字；借的时候把它拆成三层，只拿中间那层：

| 层 | 是什么 | 怎么对待 |
|---|---|---|
| 问题 | 它在替用户解决什么 | 谁都可以解决同一个问题 |
| 机制 | 用什么结构解决：主屏形态、数据画成什么形状、信息出现的顺序、网格关系、一种交互 | **可以借，这是借鉴** |
| 表达 | 长成什么样：配色、字体、形状语言、插画与图标、文案口气、题材隐喻，合起来是它的那张脸 | **不借。从这次的题材、内容、品牌里重新长** |

1. 一个来源只借一条机制，写成一句不带它外观的话。「进度是一条实心加刻度的条，做完的是实心」是机制；「蓝底黄胶囊」是表达。检验：只把这句话交给没见过原作的人，他画不出原作。
2. 机制尽量跨类目借。给记账 App 借潮汐 App 的曲线、给菜谱 App 借相机 App 的拨盘，自然就不像；同类目的出色作品用来知道行业的底线和这次要避开的样子。媒介仍然要相同（App 借 App、网页借网页）。
3. 画面上最显眼的那一处必须是自己的：题材里才有的东西（方向卡的「form 来自内容的哪里」），不是借来的那条机制。借来的机制是骨头，这次的题材是脸。能把两个来源的机制杂交、或让一条机制撞上题材里的一个意象，比单借一个强。
4. 做完跑认得出测试（4d 第 5 条）。
5. 来源写在卡上、摆给用户时一句话说明借了谁的什么。说得出口的是借鉴；需要藏的，多半是抄。

**用户指定了风格或品牌时**：六个候选都在那个语境里各出一种诠释，颜色可以都受品牌约束（compare 加 `--brand`，只比骨架）；轮盘只在和语境兼容的风格里抽。「Apple 风格」是一个语境不是一个设计。

**4b · 写六张方向卡**，写进项目目录的 `directions.md`，每张一段：

| 栏 | 写什么 |
|---|---|
| 逻辑与来源 | 哪位设计师 / 哪个作品（附出处和参考板路径）/ 抽到几号哪个风格 |
| 借的是什么 | 从来源里拆出来的那一条机制，一句不带原作外观的话，附量出来的数（`ref_card.py measure`）：网格、字号关系、面积比例、图文关系、数据的形状 |
| 不借的、自己长的 | 原作的表达层里这次明确不拿的（它的配色、字体气质、形状语言）；这次的颜色、字体、形状各从题材的哪里来 |
| 主角素材 | 画面主角是什么：真图、生成图、程序化材质、数据图像、巨字……（档位见 `references/materials.md`） |
| 骨架 | 版式结构一句话 |
| 胆量花在哪 | 唯一一处最大胆的地方，其余服务内容 |
| form 来自内容的哪里 | 一句话：这个设计里哪个东西是这个题材才有的 |

**4c · 不画缩略图页。** 六个候选停在方向卡上：每张卡把「主角素材」「骨架」「form 来自内容的哪里」写具体，具体到读卡的人能想出那一屏长什么样。写不具体的卡说明这个候选还没想清楚，换来源重写，不靠画一格小图来试。（3.4.2 起去掉了六格缩略图页：用户看的是三张完整版，那一页在凑数。）

**4d · 挑三张做完整版**，标准按顺序：

1. **单看就够好**：拿出去不丢人。方向卡上都说不出主角和骨架的，完整版也救不回来。
2. **三张彼此不一样**：骨架不同、气质不同（大胆／中性／安静不必凑齐，但别三张都同一温度）、不挤在同一个外观家族。
3. **不撞最近的项目**：外观账本里刚用过的样子和参照，这次不选。
4. **不用力过头**：把整页做成道具或实物仿制、套万能隐喻（地铁线路图、终端命令行、报纸头版、仪表盘）、饱和度字号全部拉满——三张里最多一张这样，而且只在内容真需要时。判断方法：**把这个手法去掉，信息是更清楚还是更糊？** 去掉反而更清楚，它就是过头。

5. **认得出测试**：每个有现实参照的完整版做完后，把它和参照并排：

   ```bash
   python3 "$HD/scripts/ref_card.py" compare --ref refs/board-1.jpg --mine design-demos/shot-dir-1.png --out refs/card-dir-1.jpg
   ```

   打开并排图，把两边的字都当作看不见：熟悉原作的人会不会说「这是它的新版本」？会，就保留机制、把表达层（颜色、形状语言、字体气质）换掉重做。再看想借的那条机制到位没有，没到位也回去改。脚本给的差值只是辅助，一张图里底色面积不同就能把数字拉开，最后以眼睛为准。结论写进 `polish-log.md`。

三张不必一套逻辑各一张：两张最佳设计师加一张轮盘也可以，选最强的。没选上的三张留着，展示时一起给用户看。

一个例子（题材：一家做了三代的手工酱油厂官网）：

- 最佳设计师｜原研哉｜借的：大量留白、素材本身做主角、极少的字｜主角：陶缸与晒场的真实照片｜骨架：一屏一张图一句话，纵向慢节奏｜胆量：首屏一整张盐霜特写｜form：酱油要晒 180 天，节奏就放慢
- 现实参照｜一个获过奖的日本老字号食品官网（附截图）｜借的：竖排标题与横排说明的关系（标题列占宽 18%）、全站只有两色且副色不到一成｜不借的：它的朱红与和纸底、明朝体；这次的颜色取自酱缸的釉色和盐霜，字用宋体｜主角：产品瓶身实拍＋竖排标题｜骨架：左竖排标题、右三栏内容｜胆量：只用两种色｜form：老字号的「方子」气质
- 秒数轮盘｜抽到「媒体级粗野主义」｜借的：大字号反差和模块网格｜主角：超大汉字「酱」切进首屏｜骨架：模块网格，图文交错｜胆量：首屏字号反差｜form：一个字讲完一家酱园

### Phase 5 · 并行构建，每版自检

每个 subagent 只拿 spec ＋ 自己那一张方向卡（含参考板或样张图）＋ 共用素材，独立 context、互不参考。不支持 subagent 的 runtime 串行做，每版开工前只读 spec 和自己的卡，不参考已做的版本。

构建规则（三版共用）：

- 用户真实内容，不用 Lorem；三版同内容只换设计
- 可读性硬底线：网页正文 ≥14px、标签 ≥12px；deck 正文 ≥24px、标签 ≥16px；手机看的 1080 宽长图正文 ≥36px、标签 ≥28px；正文对比度 ≥4.5:1；留白要是构图，不是内容缺席
- 单文件 HTML；单文件交付时图片和 logo base64 内嵌
- deck 用 deck 外壳，每方向出 2 页代表页（`references/modules/deck.md`）
- App 原型的多屏不要只排成一排手机，展示板构图见 `references/app-prototype.md`「展示板」
- 三个完整版存 `design-demos/dir-1.html`、`dir-2.html`、`dir-3.html`（deck 是 `dir-1/` 等子目录），截图 `npx playwright screenshot file:///… out.png --viewport-size=1440,900`（deck 用 1920,1080）

三版都做完后，每版先过一轮打磨环（`references/polish-loop.md`）：

```bash
python3 "$HD/scripts/polish.py" shot design-demos/dir-1.html --mobile    # 逐屏看原尺寸截图，写下最伤的三处，改；dir-2、dir-3 同样
```

初稿是给用户选方向的，一轮就够，但这一轮不能省：首屏不成立、主角素材缺席、往下全是一样的卡片，这三类问题要在摆出来之前解决。然后跑：

```bash
python3 "$HD/scripts/design_lint.py" check design-demos/dir-*.html       # 红灯必修；黄灯是顺手的模板装饰，删掉；外观家族只是提示
python3 "$HD/scripts/design_lint.py" compare design-demos/dir-*.html     # 两版撞了 → 换成备选里的另一张，或换骨架，不是换颜色
#   品牌约束了颜色字体加 --brand；App 原型多台手机并排加 --ignore-layout；deck 加 --viewport 1920x1080 --min-body 24 --min-label 16
python3 "$HD/scripts/design_lint.py" ledger check design-demos/dir-*.html # 和最近项目撞了 → 换成备选里的另一张
```

完整版命名 `design-demos/dir-1.html` 到 `dir-3.html`，确认真有 3 个再往下。黄灯删掉那个结构就好，换个符号躲过检测不算改；外观家族不用改，它只在三版挤在一起、或撞了账本时才有意义。没装 Python 版 playwright 时脚本会跳过并提示安装，这时用截图肉眼对照三版，并把这件事写进交付说明。

### Phase 6 · 展示，然后停

一起摆出三张完整版截图，每版附它的方向卡摘要（逻辑与来源、借的是什么、主角素材）和一句「form 来自内容的哪里」；再用一两句话各说一下没做的另外三个候选，说一句「这三个是备选，看中哪个我做成完整版」。摆出来就结束这一回合等用户选，包括无人值守会话。

### Phase 7 · 用户选了之后

- 把「展示了哪几版、截图路径、用户的原话」写进 `direction-approved.md`
- 用户的话里有对品味的明确表态（「这个完全不 AI 感」「太素了」「要更像杂志」），用 `learn.py add --kind preference` 逐字记下，并写明适用范围
- 混合选择（「A 的布局＋C 的颜色」）照做，记下他混的是哪两栏——这比记住他选了哪个颜色有用；他说某版「过头」「太素」也逐字记下
- 进入执行；交付后 `design_lint.py ledger add <最终文件> --project <名字> --note "<来源：设计师/作品/风格>"` 记一笔外观账，下次连参照一起避开
