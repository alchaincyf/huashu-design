# 分发经验（huashu-design）

跨项目复现过、或测量过、对任何用户都成立的发现。`learn.py` 开工前会按主题把匹配的条目带出来。

维护规则见 `references/evolution.md`：只在仓库里手改；reference 吸收了某条就删掉它；一个用户的口味不进这里。

## S1 · verified · topics: direction, color, typography

- 发现：不加约束时，三个方向会一起滑向暖奶油底＋高反差衬线标题＋陶土色点缀。这是模型自己的默认审美（Anthropic 的交互配色），Anthropic 官方 frontend-design skill（2026）把它列为 AI 生成页面聚类特征的第一条。但这个家族本身不丑，问题是三版挤在一起、项目之间反复出现（见 S6）。
- 下次：三版别挤在同一个外观家族；`design_lint.py compare` 会报「三版落在同一个外观家族」，`ledger check` 会报和最近项目撞了。
- 证据：skill 开发期的内部自测与多个项目的三方向截图（2026-10 盘点，未公开）；官方原文 https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md

## S2 · verified · topics: direction, layout

- 发现：三版只换配色字体、共用一个布局骨架，评审和用户都会一眼认出是换皮。差异要落在信息的组织方式上。
- 下次：三张方向卡的骨架要互不相同；`compare` 的骨架相关过高就回到卡片换骨架或换来源。注意别矫枉过正——强制每版套一个隐喻会让页面用力过头（见 S5）。
- 证据：skill 开发期的内部盲测与 2026-10 盘点（未公开）。

## S3 · verified · topics: readability, quiet, whitespace

- 发现：安静、奢侈留白的风格做过头会变成大片死白加微缩字号，第一眼像页面没渲染完，输给普通的基线版本。
- 下次：字号与对比度底线（网页正文 ≥14px、deck ≥24px、手机长图 ≥36px 画布像素，对比度 ≥4.5:1）任何风格都不豁免；`design_lint.py check` 会亮红灯。
- 证据：skill 开发期的内部盲测评审（未公开）。

## S4 · verified · topics: assets, logo, single-file

- 发现：要双击打开的单文件 HTML，用相对路径引用图片和 logo，挪个目录就全部裂图。
- 下次：单文件交付一律 base64 内嵌；`design_lint.py check` 对相对路径图片亮黄灯、对已裂的图亮红灯。
- 证据：盲测里六个产品按钮全部裂图直接输掉评审。

## S5 · verified · topics: direction, metaphor, intensity

- 发现：为了拉开三方向而强制每版先定一个「大想法隐喻」，会让页面被整个做成道具（档案柜、借书卡、处方笺）或套上万能隐喻（地铁线路图、终端、报纸头版）。三方向确实拉开了，但盲选输给了不加这条约束的版本，而且同一个地铁图在两个不相干的题目里各出现一次——换了一种新的雷同。
- 下次：三张完整版里最多一张把整页做成道具或套万能隐喻；判断方法是去掉这个手法，信息是更清楚还是更糊。
- 证据：2026-10 改版的改前改后盲选（4 题新做法只赢 1 题）与 4 题里新做法两次用到地铁线路图（skill 开发期内部基准，未公开）。

## S6 · verified · topics: direction, constraint, boring

- 发现：为了避开 AI 默认外观加的约束（三版最多一版暖纸衬线、外观家族亮黄灯、用力过头配额），让三版一起退到浅冷色、规整网格，被用户评为「太规整，太无聊了」，盲选又输给了不加这些约束的旧做法。旧做法里被认可的几版，恰好是深底单点缀和暖纸衬线。约束只能减少选项，减少不出好设计。
- 下次：加选项，不加禁令——每套逻辑出两个候选、先画缩略图再挑；风格从样张里看、参考从截图里拆。外观家族只用来比三版、比账本。
- 证据：2026-10 第二轮改前改后盲选（2 题，改版两题都输），skill 开发期内部基准，未公开。

## S7 · observed · topics: direction, reference, medium

- 发现：现实参照选同一媒介的获奖作品（App 参照 Apple Design Award 获奖 App、书店 deck 参照 Stripe Press）的方向被认可；跨媒介参照（deck 参照 1935 企鹅平装封面、App 参照植物标本台纸）一个用力过头、一个无聊。
- 下次：现实参照优先同媒介；跨媒介的只借色彩或字体关系，不借版式。
- 证据：2026-10 第二、三轮盲选共 4 个现实参照方向，样本小，待更多项目验证。

## S8 · verified · topics: direction, style, reference

- 发现：「加选项，不加禁令」在盲选里赢了——三套逻辑各出两个候选、先画缩略图再挑三张，风格从样张里看、参考从截图里拆，外观家族不再亮黄灯。同两道上一轮输掉的题，改版两题都被选中，用户评价「这次明显变好了」。
- 下次：遇到「太单调」「太像 AI」，先加候选和参考，别先加禁令；新禁令要先过一轮盲选。
- 证据：2026-10 第三轮改前改后盲选（2 题，改版两题都赢），skill 开发期内部基准，未公开。

## S9 · observed · topics: app, reference, appstore

- 发现：把两届 App Store Awards 入围的 90 个 App 的商店截图取全（89 个、1572 张）逐个看，出色的那些主屏很少是「导航栏＋卡片列表＋tab」，而是从「这件事在现实里长什么样」长出来的；只凭名字搜截图会配错 App（同厂另一款），要用 id。
- 下次：App 原型的现实参照用 `appstore_shots.py` 按 id 取图再拆；范式卡 `app-paradigms.md` 只当候选来源。只看过商店截图，流程与动效没有结论，别从范式卡里推。
- 证据：2026-11 走查，未装机；范式卡对原型质量的提升还没有经过用户盲选，待验证。

## S10 · observed · topics: reference, direction, originality

- 发现：参考看得越清楚，越容易做成它的翻版。首轮实测里，取了真实商店截图当现实参照的那个方向，和参照 App 的底色、强调色、进度条形状都贴上了；用色板距离这类数字查不出来（两张图底色面积不同就把数拉开了），并排一看就认得出。
- 下次：参考拆三层，只借机制、表达从题材重新长，机制尽量跨类目借；做完和参照并排，以眼睛为准跑认得出测试（`directions.md`「借一层，不借一身」）。
- 证据：2026-11 一道 App 原型题、一次实跑，样本小；规则加上之后的效果待更多项目验证。

## S11 · verified · topics: material, image, app

- 发现：同一张 App 样张，把代码画的实物（纸箱、盆栽）换成生成的照片，其余一行不改，可信度差别很大。在不能生图的环境里借本机的 Codex CLI 生成是通的，一张不到一分钟；但 agent 拿不到生图能力时会用代码拼一张图交差，只查「文件在不在」会被骗。
- 下次：该是图的地方按「环境自带生图 → 借本机 Codex（`gen_image.py`）→ 生图 skill → 开放许可真图」的顺序取，不拿 emoji、手画 SVG、占位块顶替；验真只认生成目录里本次新出现的文件。
- 证据：2026-11 范式样张 01、06 换图前后对照；`gen_image.py` 在 Claude Code 里实跑两张。

## S12 · verified · topics: lint, compare, runtime

- 发现：方向比对脚本在四组肉眼明显不同的 App 三方向上全部报「撞了」，原因不是阈值：展示板上并排的四台手机机身被数成了「同一圆角同一阴影的卡片套件」；宣传图读到的是预览页灰边；「有色底」不分红黄。环境识别同理：在 Claude Code 里启动的 Codex 继承了外层的环境变量，只看变量会认错。
- 下次：检查报了和眼睛相反的结论，先去找它量错了什么，再考虑动阈值；识别运行环境先看父进程链，环境变量兜底。
- 证据：2026-11 五组真实三方向产物修前全报撞、修后全部通过；真实 Codex 会话里实跑 capabilities.py 认出 Codex；WorkBuddy 的标记（CODEBUDDY=1）来自它随包的命令行代码；2026-11-20 在运行中的 WorkBuddy 5.11.3 与豆包工作 2.31.0 里实跑，分别认出（依据环境变量／父进程）。

## S13 · verified · topics: material, image, runtime

- 发现：「环境自带生图」不等于拿到的图能直接用。WorkBuddy 的 ImageGen 出的图右下角带「AI生成 / WORKBUDDY」水印，工具的 footnote 参数传空、传空格、传自定义文字都不起作用，设置页九个分类里也没有开关；豆包工作的 image_gen 只返回云端网址，要自己下载落盘，高一档的模型要会员、会自动降档，而且会出现说完「现在生成」就停下、追问一句才真的生成的情况。
- 下次：自带生图出的图先打开看四个角，带平台水印就改用下一个来源；工具给网址就立刻下载；说了要生成之后去目录里确认文件真的出现了。
- 证据：2026-11-20 在 WorkBuddy 5.11.3（体验版账号）与豆包工作 2.31.0（本地电脑模式）里各实跑一次同一条指令，另加 WorkBuddy 三组水印对照；付费套餐下是否不同未验证。

## S14 · verified · topics: direction, workflow

- 发现：六格缩略图页在实际使用里没有起到「先看再挑」的作用，用户看的是三张完整版，那一页成了每次都要多做的凑数页。
- 下次：六个候选停在方向卡上，卡写具体；直接挑三张做完整版，另外三个用一两句话告诉用户。
- 证据：2026-11-20 用户在一道网页三方向题进行中明确要求去掉这一步，原话记在本机经验里；去掉之后三方向质量有没有变化，待后续项目观察。
