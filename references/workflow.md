# Workflow：从接到任务到交付

这份文件是三方向选定之后的主干流程，以及开工前怎么问问题。

对齐发生在两个地方：开工前的一轮提问，和三方向的选择。用户看着真实初稿选定方向之后，方向就对齐完了——接下来一口气做完、打磨好再交，不要每一步都停下来请他确认。只有没走三方向的任务（用户明说跳过）才需要下面的「早对齐模式」。

## 标准流程（三方向选定之后）

1. **理解需求**：涉及具体产品、技术、事件时，第一个动作是 WebSearch 核实存在性、发布状态、版本、规格，写进项目的 `product-facts.md`——这步在问问题之前。三方向 Phase 1 已经问过的不再问；没走三方向的新任务（例如方向豁免后）问一轮，小修小补跳过。
2. **探索资源、抽核心资产**：读 design system、链接、截图、代码。涉及具体品牌走品牌资产协议，产出 `brand-spec.md`。开工前确认核心资产到位：实体产品有产品图、数字产品有 logo 和 UI 截图、色值从真实 HTML/SVG 抽取。缺了就停下补。
3. **先答 form 五问，再规划系统**（每个页面、屏幕、镜头开工前）：
   - **叙事角色**：hero / 过渡 / 数据 / 引语 / 结尾？
   - **观众距离**：10cm 手机 / 1m 笔记本 / 10m 投屏？决定字号和密度
   - **视觉温度**：安静 / 兴奋 / 冷静 / 权威 / 温柔 / 悲伤？
   - **容量估算**：画 3 个 5 秒小草图，算内容塞不塞得下
   - **视觉母题**：这个内容独有、别的题材不会有的视觉元素、结构或隐喻是什么？答不出说明还在靠风格标签抽签

   答完再定设计系统（色彩、字型、版式节奏、组件模式），系统服务于答案，写在 HTML 开头的注释里。交付时写一句「form 来自内容的哪里」。
   走过三方向的任务不在这里停：方向卡和用户的选择已经定了系统。没走三方向的任务，把五问答案和系统说出来，等用户点头再写代码。
4. **建文件夹**：`项目名/` 下放主 HTML 和需要的素材（不要整批复制 >20 个文件）。
5. **对齐 pass**（只用于没走三方向的任务，或页数多、流程长的大项目）：HTML 开头写 assumptions＋占位＋推理注释，尽早给用户看一次，等反馈再写组件。走过三方向的常规任务跳过这一步。
6. **Full pass**：把选定的方向做成完整作品，做变体、加 Tweaks。多页的 deck 和多屏的原型先定 2 页代表页再批量，其余情况一口气做完。
7. **打磨与验证**：打磨环至少 2 轮（`python3 "$HD/scripts/polish.py" shot`，逐屏看原尺寸截图、写下最伤的三处、改，见 `references/polish-loop.md`）；查控制台报错、`python3 "$HD/scripts/design_lint.py" check`（红灯必修）；交互逐个点一遍——AI 写的交互经常有 bug。
8. **交付与回流**：总结只说 caveats 和下一步；`design_lint.py ledger add` 记外观账；`learn.py harvest` 看有什么值得记（`references/evolution.md`）。

**检查点原则**：必须停的地方只有 SKILL.md 窄桥里写的那几处（三方向摆出来、gate 文件要求的确认）。停的时候说清「我做了 X，下一步打算 Y」，然后真的等。「继续」授权的是进入下一步，不是跳过这一步里的 gate。其余时候往前做，把你替用户定的事写成假设，交付时列出来。

## 异常处理

| 场景 | 处理 |
|---|---|
| 需求模糊到无法着手 | 列 3 个可能的方向（如「落地页 / Dashboard / 产品详情页」）让用户选，不要直接问 10 个问题 |
| 用户说「不要问了，直接做」 | 问题可以不问（自己补 assumption），三方向照走；只有用户明说「别出三版 / 一版就行」才降为 1 主＋1 变体，并在 `direction-approved.md` 记原话 |
| 参考图和品牌规范打架 | 停下，指出具体矛盾（「截图是衬线，规范写的是无衬线」），让用户选 |
| 起手组件加载失败 | 先查 `references/react-setup.md` 的报错表；还不行就降级纯 HTML+CSS |
| 时间紧，「30 分钟内要」 | 跳过对齐 pass 直接 full pass，只做 1 个方案，交付时标注「未经早期确认」 |
| 单个 HTML >1000 行 | 按 `references/react-setup.md` 拆成多个 jsx，末尾 `Object.assign(window, …)` 共享 |
| 克制原则和产品需要的信息密度冲突 | 产品卖点是 AI、数据、上下文感知（Dashboard、Tracker、Copilot、健康、记账）时走高密度：每屏 ≥3 处有内容的差异化信息；装饰性 icon 照样不要 |

异常时先用一句话告诉用户发生了什么，再按表处理，不要静默决策。

## 问问题的艺术

整个项目只问一轮：走三方向的任务在 Phase 1 问（最多 3 个问题＋一次问全参考材料），下面的清单是题库，从里面挑最影响结果的，不是每题都问。不是走过场，是真的要把需求摸清；但别为了凑数问——推得出来的自己定，标注依据。用户不回应就按最佳判断补齐假设往下做，用看得见的东西代替追问。

**什么时候要问**：新任务、模糊任务、没有design context、用户只说了一句模糊的要求。

**什么时候可以不问**：小修小补、follow-up任务、用户已经给了明确PRD+截图+上下文。

**怎么问**：大部分 agent 环境没有结构化问题 UI，在对话里用 markdown 清单问即可。**一次性把问题列完让用户批量答**，不要一来一回一个个问——那会浪费用户时间、打断用户思路。

## 题库

下面五类是可以问的问题，不是每题都要问：从里面挑最影响结果的，一次最多 3 个，其余的自己按最佳判断定下来、写成假设。

### 1. Design Context（最重要）

- 有没有现成的design system、UI kit、组件库？在哪？
- 有没有品牌指南、色彩规范、字体规范？
- 有没有可以参考的现有产品/页面截图？
- 有没有codebase可以读？

**如果用户说"没有"**：
- 帮他找——翻项目目录、看有没有参考品牌
- 还没有？明确说："我会基于通用直觉做，但这通常做不出符合你品牌的作品。你考虑下是否先提供一些参考？"
- 实在要做，就按`references/design-context.md`的fallback策略办

### 2. Variations维度

- 三方向之外，用户还想在哪些维度上看变体？（三个方向本身是固定的，不用问要几种）

### 3. Fidelity和Scope

- 多高保真？线框图 / 半成品 / 真实data的full hi-fi？
- 覆盖多少flow？一屏 / 一个flow / 整个产品？
- 有没有具体的「必须包含」元素？

### 4. Tweaks

- 希望能实时调整哪些参数？（颜色/字号/间距/layout/文案/feature flag）
- 用户自己要不要在做完后继续调？

### 5. 任务专属

针对具体任务的细节。例如：

**做landing page**：
- 目标转化动作是什么？
- 主要受众？
- 竞品参考？
- 文案谁提供？

**做iOS App onboarding**：
- 几步？
- 需要用户做什么？
- 跳过路径？
- 目标留存率？

**做动画**：
- 时长？
- 最终用途（视频素材/官网/社交）？
- 节奏（快/慢/分段）？
- 必须出现的关键帧？

## 问题模板示例

遇到新任务时，从题库里挑出最多 3 个问题，用这样的口气一次问完：

```markdown
开始前想跟你对齐三件事，一次回我就行；不方便回我就按括号里的假设先做：

1. 这页最想让人做的一个动作是什么？（我先假设是下载）
2. 有没有你喜欢的参考、现成的 logo 或品牌色？（没有的话我从题材里定）
3. 主要在手机上看还是电脑上看？（我先两边都做）
```

## 早对齐模式

用于没走三方向的任务（用户明说跳过三版）和页数多、流程长的大项目。走过三方向的常规任务已经对齐过了，直接做完。步骤：

### Pass 1：Assumptions + Placeholders（5-15分钟）

HTML文件头部先写你的**assumptions+reasoning comments**，像设计师把草图摊给客户看：

```html
<!--
我的假设：
- 这是给XX受众看的
- 整体tone我理解为XX（基于用户说的"专业但不严肃"）
- 主要flow是A→B→C
- 色彩我想用品牌蓝+暖灰，不确定你想不想要accent色

未解的问题：
- 第3步的数据从哪里来？先用placeholder
- 背景图用抽象几何还是真照片？先占位

如果你看到这里觉得方向不对，现在是成本最低的时候改。
-->

<!-- 然后是带placeholder的结构 -->
<section class="hero">
  <h1>[主标题位 - 等用户提供]</h1>
  <p>[副标题位]</p>
  <div class="cta-placeholder">[CTA按钮]</div>
</section>
```

**保存 → show用户 → 等反馈再走下一步**。

### Pass 2：真实组件+Variations（主力工作量）

用户批准方向后，开始填充。这时：
- 写React组件替换placeholder
- 做variations（用design_canvas或Tweaks）
- 如果是幻灯片/动画，用starter components起手

**做到一半再show一次**——不要等全做完。设计方向错了，晚show等于白做。

### Pass 3：细节打磨

用户满意整体后，打磨：
- 字号/间距/对比度微调
- 动画timing
- 边界case
- Tweaks面板完善

### Pass 4：验证+交付

- 用Playwright截图（见`references/verification.md`）
- 打开浏览器肉眼确认
- 总结**极简**：只说caveats和next steps

## Variations的深度逻辑

给variations不是给用户制造选择困难，是**探索可能性空间**。让用户mix and match出最终版本。

### 好的variations长什么样

- **维度明确**：每个variation在不同维度上变（A vs B只换配色，C vs D只换layout）
- **有梯度**：从「by-the-book保守版」到「大胆novel版」逐级递进
- **有记号**：每个variation有短label说明它在探索什么

### 实现方式

**纯视觉对比**（静态）：
→ 用`assets/design_canvas.jsx`，网格布局并排展示。每个cell带label。

**多选项/交互差异**：
→ 做完整原型，用Tweaks切换。例如做登录页，"布局"是tweak的一个选项：
- 左文案右表单
- 顶部logo+中央表单
- 背景全屏图+浮层表单

用户开关Tweaks就能切换，不需要打开多个HTML文件。

### 探索矩阵思考

每次设计，脑内过一遍这些维度，挑2-3个来给variations：

- 视觉：minimal / editorial / brutalist / organic / futuristic / retro
- 色彩：monochrome / dual-tone / vibrant / pastel / high-contrast
- 字型：sans-only / sans+serif对比 / 全衬线 / 等宽
- Layout：对称 / 非对称 / 不规则grid / full-bleed / 窄栏
- Density：稀疏呼吸 / 中等 / 信息密集
- 交互：极简hover / 丰富micro-interaction / 夸张大动画
- 材质：flat / 有阴影层次 / 纹理 / noise / 渐变

## 遇到不确定的情况

- **不知道怎么做**：坦白说你不确定，问用户，或先做个placeholder继续。**不要编**。
- **用户的描述矛盾**：指出矛盾，让用户选一个方向。
- **任务太大一次吃不下**：拆成steps，先做第一步让用户看，再推进。
- **用户要求的效果技术上很难**：说清技术边界，提供替代方案。

## 总结规则

交付时，summary **极短**：

```markdown
✅ 幻灯片已完成（10张），带Tweaks可切换"夜/日模式"。

注意：
- 第4页的数据是假的，等你提供真数据我替换
- 动画用了CSS transition，不需要JS

下一步建议：先你浏览器打开看一遍，有问题告诉我哪页哪处。
```

不要：
- 罗列每一页的内容
- 重复讲你用了什么技术
- 夸自己设计多好

Caveats + next steps，结束。
