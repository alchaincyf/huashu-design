# 稳妥轨道：没把握时，从做到位的东西改起

这条轨道给三种情况用：

- 你做出来的东西自己看着撑不住——缩略图检查没过、`design_lint.py` 的红灯修了两轮还在、打磨环看下来整页平庸
- 运行环境受限——没有看图能力、上下文吃紧、轻量模型
- 时间很紧，要先保住下限

思路只有一条：**不从白纸开始，每一步都从一个已经做到位的东西改起。** 走这条轨道做出来的不会是最惊艳的，但不会是「米色底、三张卡片、一百行 HTML」那种一眼草稿。
三方向门、品牌资产协议、可读性底线照常，轨道只改变「怎么做出来」。做顺了随时可以离开轨道，按自己的判断做。

## 1 · 六个候选从样张里来

`assets/style-specimens/` 里每种风格都有一份做到位的样张：一张 `.jpg` 和同名的 `.html` 源码（一屏，1200×750）。

1. 用看图能力打开对应分区的总览图 `sheet-<web|ppt|info|app|xhs>.jpg` 和跨媒介的 `sheet-east.jpg`。
2. 三套逻辑照旧，各出两个候选，但每个候选都落到一份样张上：
   - 秒数轮盘 ×2：按 `references/directions.md` 的办法抽两份
   - 最佳设计师 ×2：想好两位设计师后，各找一份气质最接近他的样张当起点（卡上写「设计师某某，以样张 NN 起步」）
   - 现实参照 ×2：参照作品截到了图就照图拆规则；截不到，就找版式最接近它的样张起步，卡上如实写「未亲眼看到，以样张 NN 代替」
3. 六份样张要彼此不一样：别挑六份深色的，也别挑六份都是大字的。

## 2 · 缩略图：把样张改成这个项目的

每一格缩略图这样做：

1. 读那份样张的 `.html` 源码，把它的 `<style>` 和主体结构搬进缩略图的一格（样张是 1200×750 的一屏，外面套一层 `transform: scale(0.4)` 缩进格子；每格的容器加 `data-thumb="1"`…`"6"`；不同样张的 class 名会撞，给每格的选择器加上各自的前缀）。
2. 改三样，一样都不能留样张原来的：
   - **字**：换成这个项目的真标题、真内容。样张里的题材和数字都是虚构的。
   - **色**：按 `references/design-styles.md` 的色彩推导协议，从这个题材里重新采色（它的材料、产地、器物、真图里的主导色），替换样张的色值。
   - **主角图形**：样张里的主视觉（一个星球、一张唱片、一座山）换成这个题材世界里的东西。
3. 留下的是样张的骨架、字号关系和气质。

然后跑 `python3 "$HD/scripts/polish.py" thumbs design-demos/thumbs.html`，没有 ✗ 再挑三张。

## 3 · 完整页：先写逐屏稿，再写代码

样张只有首屏。最常见的失败是首屏有设计，往下全是「一行小标签＋一句大字」或「小标题＋三张一样的卡片」重复到底。
治它的办法是写代码之前先写一张逐屏稿，存成项目里的 `screens.md`，每个方向一张：

| 屏 | 讲哪条内容 | 用什么形式 | 这一屏的主角 |
|---|---|---|---|
| 1 | 一句话定位 | 首屏（来自样张骨架） | 四层海拔的剖面图 |
| 2 | 为什么做它 | 故事长段 | 「多云」两个字和山脊上的雷暴 |
| 3 | 怎么做的 | 前后对比 | 9 公里一格对 1 公里一格 |
| … | | | |

规则三条：用户给的每一条内容都要落在某一屏上；**相邻两屏不用同一种形式**；每一屏的主角写得出来（写不出来，这一屏就还没设计）。

形式从下面的菜单里挑，按内容挑，不按顺序挑：

| 形式 | 适合讲什么 | 做法一句话 |
|---|---|---|
| 产品界面＋标注 | 功能长什么样 | 画出界面，用细线引出两三条说明 |
| 可以玩的演示 | 产品的核心机制 | 一个滑块、一组切换、一个拖动，拨一下画面跟着变 |
| 数据即图像 | 一个关键数字或一组数 | 把数字画成刻度、面积、长度、密度，不做成数字卡片 |
| 前后对比 | 以前怎样、现在怎样 | 左右或上下两幅同构的画面，只有一处不同 |
| 剖面或地图 | 空间、层级、路线 | 一张贯穿全宽的图，文字标在图上 |
| 时间轴 | 过程、48 小时、一天的节奏 | 横向刻度，事件挂在刻度上 |
| 大字声明 | 一句最重要的话 | 一屏只放一句，字大到成为画面 |
| 故事长段 | 起因、作者是谁 | 窄栏、大行距、像一页书，配一张图或一个年份 |
| 图文对开 | 一个功能的展开说明 | 一半图一半字，下一个功能左右对调 |
| 清单或规格表 | 覆盖范围、参数、平台 | 细线表格或两栏清单，不加卡片 |
| 价格对比 | 免费和付费 | 两栏并排，差别逐行对齐 |
| 行动收尾 | 下载、联系 | 一个动作，周围留空 |

一个落地页用到五六种形式是正常的。逐屏稿写完再开始写 HTML，一屏一屏写，每屏都继续用首屏定下的那套字号阶梯（4–5 级）、颜色、线条和间距节奏。

落地页逐条对：

- [ ] 首屏：一句话、主角素材、一个主要动作
- [ ] **产品看得见**：介绍 App 就把界面画出来（`assets/ios_frame.jsx`，或手写一个简化的界面，里面填用户给的真实内容）；介绍数据产品就把数据画成图。只用文字描述产品的页面不算完成
- [ ] 逐屏稿 `screens.md` 写了，页面和它对得上
- [ ] 每个功能用不同的形式讲：一个产品界面加标注、一个整幅图表、一个可以玩的演示——不要三张一样的卡片并排
- [ ] 起因或故事单独占一屏，用大字或图
- [ ] 用户给的每一条内容都上了页面，没有编他没给的数据、评价、logo
- [ ] 每一屏至少有一个图形或一处大字（`polish.py shot` 会报「连续几屏只有文字和框」）
- [ ] 390 宽的手机上不坏、字不小于 16px
- [ ] 厚度：一个完整落地页的 HTML 通常在 400 行以上。只有一百来行，多半只搭了骨架

deck 的对应清单在 `references/modules/deck.md`，小红书图文本来就从模板起步（`references/modules/xiaohongshu.md`），App 原型见 `references/app-prototype.md`。

## 4 · 颜色和字体的安全做法

- 颜色：2–3 个有彩色加一组中性色，全部从题材里采，写一句「为什么是这个色」。写不出这句话就是在抄配方。
- 字体：从 `references/typography.md` 的配对表里选一对，标题和正文各一种，不要第三种。
- 不确定时宁可对比强一点：标题和正文的字号至少差 2.5 倍，比「什么都差不多大」安全。

## 5 · 交之前

```bash
python3 "$HD/scripts/polish.py" shot <页面.html> --mobile     # 逐屏看；没有看图能力就对照上面的清单和它打印的事实
python3 "$HD/scripts/design_lint.py" check <页面.html>         # 红灯必修，黄灯删掉
```

打磨环照 `references/polish-loop.md` 走。交付时如实说明哪些步骤是照轨道做的、哪些没做（比如「没有看图打磨」）。
